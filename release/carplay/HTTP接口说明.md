# 四轮差速小车 HTTP 接口说明

文档版本：1.3　日期：2026-09-30  
对应实现：当前工程 `carplay.ino`、`MotionControl.h`、`CarConfig.h`。文档版本不是 URL 版本号。

## 1. 接入方式

手机、电脑或其他控制终端连接小车热点后，通过 HTTP 调用接口，无需互联网。

| 项目 | 当前配置 |
| --- | --- |
| Wi-Fi 名称 | `Carplay-ESP32` |
| Wi-Fi 密码 | `carplay123` |
| 接口基础地址 | `http://192.168.4.1` |
| 端口 | `80` |
| 自带控制网页 | `http://192.168.4.1/` |
| 返回数据 | JSON，UTF-8；网页首页返回 HTML |
| 请求参数 | URL 查询参数，或 POST 表单 `application/x-www-form-urlencoded` |

当前不解析 JSON 请求体。热点名称、密码和 IP 以交付设备的 `CarConfig.h` 为准。当前没有 HTTP 登录或 HTTPS；`session` 是防止旧控制指令覆盖新控制者的会话编号，不是认证凭证。已接入热点的客户端可明确申请控制权或调用全局停车。

## 2. 接口一览

| 路径 | 方法 | 用途 |
| --- | --- | --- |
| `/claim` | POST | 明确切换到 Wi-Fi 控制，关闭全部电机并取得新会话编号 |
| `/move` | POST / GET | 提交前进、后退、差速转向或零速度指令 |
| `/stop` | POST / GET | 停车，清除运动指令并退出手柄遥控模式 |
| `/release` | POST / GET | 释放指定 Wi-Fi 会话，不中断新的控制者 |
| `/status` | GET | 查询当前目标轮速和控制状态 |
| `/` | GET | 打开设备自带控制页面 |

集成时建议运动、停车使用 POST。GET 为兼容及调试保留。

## 3. 控制权与运动指令

### 3.1 申请控制权 `/claim`

仅接受 **POST**，无需参数。用户明确点“激活网页控制”（手柄控制时显示“切换到网页控制”）时调用，可从手柄或另一个网页接管；调用时清除原有车轮和新增电机输出、退出手柄遥控模式并使旧会话失效。成功返回 HTTP 200，例如：

```json
{"ok":true,"session":42,"valid_ms":500}
```

`session` 是正整数（1～4294967295），每次应使用该次实际返回值，不能把示例42写死。取得会话后，需在500毫秒内发送第一条带此编号的 `/move`；此后建议每100毫秒续发，`ms=500`。只申请控制不会让电机运动。

以下情况使会话失效：手柄重新接管、全局停车、指令有效期届满、所有 Wi-Fi 客户端断开或新的 `/claim`。后续携带旧编号的运动与释放请求会被拒绝，不能影响新的控制者。**不要在409、超时或通信失败后自动 `/claim` 抢回控制；应退出操作，等待用户重新明确切换。**

### 3.2 运动指令 `/move`

| 参数 | 必填 | 类型 / 范围 | 含义 |
| --- | --- | --- | --- |
| `session` | 会话控制时必填 | 正整数，1～4294967295 | 当前 `/claim` 返回的会话编号 |
| `speed` | 是 | 整数，-255～255 | 正数前进，负数后退，0 无平移分量 |
| `turn` | 是 | 整数，-255～255 | 正数右转，负数左转，0 无转向分量 |
| `ms` | 否 | 整数，100～2000 | 本次指令有效期，单位毫秒，默认 500 |
| `aux` | 否 | 整数，0～3 | GPIO32 新增电机档位：0关闭、1低、2中、3高 |

`aux` 设置明确档位，不是“切换到下一档”命令，心跳或重试不会重复加档。省略时保留当前尚未过期的档位；超时、释放或全部停车后归零。新增电机和车轮共用本条指令的 `ms` 有效期，持续运行需续发。单独让新增电机运行可发送 `session=<当前编号>&speed=0&turn=0&aux=1&ms=500`。三档默认 PWM 为 85、170、255（8位，约33%、67%、100%），与车轮 `speed` 无关。

`speed` 和 `turn` 是 PWM 控制量，不是厘米/秒、角度/秒或转动角度。实际车速受电池、负载、地面和电机影响。每次有效指令替换上一条 Wi-Fi 指令并刷新有效期，不会排队执行。

无 `session` 请求仅为旧终端兼容保留，且只在没有有效 Wi-Fi 会话、没有手柄遥控占用时接受；新接入端应使用 `/claim` 和 `session` 流程。携带过期编号时，即使当前没有其他控制者也不会降级为旧式请求。

自带网页的车轮速度默认80%，提供20%、40%、60%、80%、100%五档，分别发送 PWM 51、102、153、204、255；方向由正负号表示。百分比表示输出档位，不是实测速度。此变更**不改变 `/move` 的参数范围，也不对直接调用者施加80%上限**；请求 `speed=255&turn=0` 仍可输出100%。

示例：已取得会话42，前进控制量160，有效期500毫秒（请替换为实际会话编号）。

```http
POST /move HTTP/1.1
Host: 192.168.4.1
Content-Type: application/x-www-form-urlencoded

session=42&speed=160&turn=0&ms=500
```

成功：HTTP 200。

```json
{"ok":true,"source":"wifi","valid_ms":500}
```

| 动作 | speed | turn |
| --- | --- | --- |
| 前进 | 160 | 0 |
| 后退 | -160 | 0 |
| 原地左旋 | 0 | -160 |
| 原地右旋 | 0 | 160 |
| 零速度 | 0 | 0 |

电机对应：M1 左前、M2 右前、M3 左后、M4 右后。左右两侧分别同速控制。内部计算 `left = speed + turn`、`right = speed - turn`；任一侧绝对值超过 255 时，两侧同比例缩放到范围内。车轮方向需按实际接线完成校准。

HTTP 接口允许 `speed`、`turn` 同时非零，实现弧线运动。自带网页和手柄采用旋转优先逻辑，旋转时把平移分量设为零。

## 4. 停车 `/stop`

无需参数。成功返回 HTTP 200：

```json
{"ok":true,"stopped":true}
```

此接口清除 Wi-Fi 与手柄运动指令、使当前 Wi-Fi 会话失效，将 GPIO32 新增电机档位归零，将手柄车轮档位恢复为默认80%，并退出手柄遥控模式。它在手柄占用控制权时也有效，不需要会话编号。返回值表示程序已接收停车命令，不代表通过传感器确认车轮已经停止，也不是锁定式急停；后续有效控制指令仍可使小车运动。

普通 Wi-Fi 操作松键可以发送 `/move` 的 `session=<当前编号>&speed=0&turn=0`；需要全局停车、退出手柄模式时调用 `/stop`。

松开行驶键只停止车轮；如需同时关闭新增电机，显式附带 `aux=0` 或调用 `/stop`。

### 仅释放网页控制 `/release`

GET / POST，携带 `session=<当前编号>`，成功返回 HTTP 200：`{"ok":true,"released":true}`。仅在编号仍有效时释放该 Wi-Fi 会话，关闭其车轮和新增电机输出；旧编号返回409、`code: "control_changed"`，不会影响已接管的手柄或新网页。

网页失焦、后台、关闭或通信异常时使用本接口；不要用 `/stop` 处理这些自动退出事件。兼容的无编号 `/release` 只允许在没有有效 Wi-Fi 会话时释放旧式 Wi-Fi 命令，不能停止手柄。

## 5. 状态查询 `/status`

无需参数。示例返回 HTTP 200：

```json
{"source":"wifi","left":160,"right":160,"ps3_online":false,"remote_mode":false,"ps3_speed_percent":80,"wifi_session":42,"aux_level":0,"aux_pwm":0,"ip":"192.168.4.1"}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `source` | 字符串 | 当前有效指令来源：`wifi`、`ps3` 或 `none` |
| `left` | 整数 | 左侧目标 PWM，-255～255 |
| `right` | 整数 | 右侧目标 PWM，-255～255 |
| `ps3_online` | 布尔值 | 最近 500 毫秒内是否收到有效手柄数据包 |
| `remote_mode` | 布尔值 | 手柄遥控模式是否已激活、占用控制权 |
| `ps3_speed_percent` | 整数 | 手柄车轮输出档位：20、40、60、80或100，默认80；满推摇杆时的PWM比例，不是实测车速 |
| `wifi_session` | 整数 | 当前有效 Wi-Fi 会话编号；0表示没有有效会话 |
| `aux_level` | 整数 | 新增电机目标档位，0～3 |
| `aux_pwm` | 整数 | 新增电机目标 PWM，默认0/85/170/255，不是实测转速 |
| `ip` | 字符串 | 小车热点 IP 地址 |

`left`、`right` 不是编码器实测轮速；即使来源为 `wifi` 或 `ps3`，两侧目标值也可能均为零。查询状态不会续期运动命令。

`ps3_speed_percent` 只表示手柄档位，不代表 Wi-Fi 指令的速度或当前物理车速。手柄输入先归一化到-255～255，再按此百分比缩放；80%时满推为±204，轻推更低。没有新增修改手柄档位的 HTTP 接口，`/move` 仍按请求中的原始 PWM 参数执行。网页在 `remote_mode=true` 时显示手柄档位并禁用网页档位选择，但保留“切换到网页控制”按钮。

`wifi_session` 用于识别控制权变化，不是保密标识；终端应使用自己明确申请得到的编号，不应从状态接口借用其他终端的编号。无会话的旧式 Wi-Fi 输出也可能在 `wifi_session=0` 时存在，应同时检查 `source`。

## 6. 错误返回

| HTTP 状态码 | 场景 | 响应说明 |
| --- | --- | --- |
| 400 | 参数缺失、非整数或越界 | JSON `error` 描述参数错误 |
| 409 | `/move` 时手柄遥控模式已激活 | JSON `code` 为 `ps3_busy` |
| 409 | `/move` 或 `/release` 的会话失效，或有受管理会话却未传编号 | JSON `code` 为 `control_changed` |
| 405 | `/claim` 使用非 POST 方法 | JSON `error` 描述应使用 POST |
| 405 | `/move`、`/stop`、`/release` 使用非 GET / POST 方法 | `{"error":"use GET or POST"}` |
| 404 | 未匹配到路由，包括 `/status` 的非 GET 请求 | `{"error":"not found"}` |

无效请求不会自动停车，也不会刷新上一条有效指令的有效期。网络断开、超时可能没有 HTTP 响应，客户端应停止续发运动请求，并在可通信时尽力发送携带自身会话编号的 `/release`。收到409时退出本地控制，不自动抢回、不自动发送全局停车。

## 7. 调用流程与控制权

1. 连接热点，GET `/status` 确认设备可达。
2. 用户明确切换到网页控制时，POST `/claim`。切换会先关闭全部电机，即使原来正在手柄控制也可成功；保存返回的 `session`。
3. 在500毫秒内开始提交带该 `session` 的 `/move`，建议每100毫秒发送、每次使用 `ms=500`。请求应串行发送，避免积压。
4. 松开行驶键时发送零车轮速度，持续续发以维持新增电机档位；切出界面时取消续发并发送带自身会话编号的 `/release`。用户明确要求全部停车时使用 `/stop`。
5. 最后一条 Wi-Fi 指令超过有效期后自动停止且会话失效；所有热点客户端断开时也会清除 Wi-Fi 指令及会话。仍有其他设备连接时，原控制端掉线依靠指令超时停车。
6. 手柄连接本身不会占用控制权。摇杆回中、肩键松开后重新按 L1+R1，可直接从网页接管，清除网页会话并关闭全部电机，车轮从默认80%档位开始。手柄失去控制权后，单独推摇杆或按 △、□ 不会干扰网页。
7. 收到409时退出本地控制、停止续发；不自动 `/claim`，不自动 `/stop`，也不以新控制者的编号发送指令。网页可显示“控制权已切换”，等待用户再次明确切换。
8. 手柄按 × 或任何终端明确调用 `/stop`，均关闭全部电机并清除控制模式和会话。手柄断连或数据超时后退出遥控模式，不会恢复旧 Wi-Fi 动作。

新增电机上电关闭，手柄接管和网页重新激活均从关闭开始。手柄激活后每按一次 △，依次切换关闭/1/2/3/关闭，按住不连跳。×、`/stop`、当前控制源超时或断连关闭新增电机；摇杆回中不关闭它。

手柄 **□ 方块键**仅在遥控模式激活时切换车轮档位，每按一次增加20%，循环80% → 100% → 20% → 40% → 60% → 80%。激活后需先松开 □ 再按下，长按不连跳。重新激活、重新连接或全部停车后，手柄车轮档位恢复默认80%（`CarConfig::PS3_DEFAULT_SPEED_PERCENT`）。□ 不改变 GPIO32 电机档位，△ 不改变车轮档位。

网页在初次打开或刷新时默认80%，激活前后均可直接选择车轮百分比档位；退出再激活保留本页面选定的车轮档位，但新增电机归零。手柄接管期间禁用网页档位操作，仍可点“切换到网页控制”接管，无需先按手柄 ×。

网页上的“激活网页控制”或“切换到网页控制”调用 `/claim`，第三方终端采用同一流程。网页初次打开、状态查询、页面恢复到前台都不会自动接管。

同一时刻只允许一个有效 Wi-Fi 会话；新会话创建后旧会话的运动、释放请求均失效。这是并发控制机制，不是身份认证；明确的 `/claim` 或全局 `/stop` 仍可由其他已连接客户端调用。电机任务约每10毫秒更新一次，这不是网络延迟或机械停车时间的保证。

## 8. 调试命令

以下在连接小车热点的 Windows 电脑中执行；申请控制会让当前所有电机停止，运动命令会使小车实际运动。将申请与运动代码一起执行，避免在控制台逐行输入时会话已经超时。

```powershell
$carBase = 'http://192.168.4.1'
Invoke-RestMethod "$carBase/status"

# 明确取得控制权，并立即发送第一条带编号的运动指令
$carClaim = Invoke-RestMethod -Method Post -Uri "$carBase/claim"
try {
    # 示例持续发送约1秒，实际时长还包括HTTP耗时
    for ($carStep = 0; $carStep -lt 10; $carStep++) {
        $carMove = @{
            session = $carClaim.session
            speed = 160
            turn = 0
            ms = 500
            aux = 0
        }
        Invoke-RestMethod -Method Post -Uri "$carBase/move" -Body $carMove
        Start-Sleep -Milliseconds 100
    }
} finally {
    # 仅释放本次会话；如果已被接管会返回409，不影响新控制者
    Invoke-RestMethod -Method Post -Uri "$carBase/release" -Body @{session = $carClaim.session}
}

# 仅在用户明确要求全部停车时单独执行
# Invoke-RestMethod -Method Post -Uri "$carBase/stop"
```

## 9. 网页集成范围

自带网页与接口同源，可以直接调用。当前固件没有配置 CORS、OPTIONS 预检或 HTTPS；部署在其他域名或 HTTPS 网站上的网页，不能假定可以直接跨域调用此 HTTP 地址。第三方网页需要先确定部署方式，再配置同源托管或合适的跨域方案。原生 App、桌面程序可按上述 HTTP 协议接入，并遵循各平台本地网络及明文 HTTP 权限要求。

本接口只包含运动控制、停车及状态查询，不包含摄像头图传、里程计或速度反馈。
